# ADR 0001. Медиатракт и источник ввода для этапа 0

Статус — принято для лабораторного прототипа, решения о выпуске зависят от сквозных испытаний.

## Медиатракт

На агенте используем `d3d11screencapturesrc` с DXGI из GStreamer 1.28.7. Прототип отдаёт H.264 constrained baseline 1280×720 при 10 FPS, с сохранением пропорций через поля при необходимости. Кодирование выполняет `x264enc` или выбранный оператором `mfh264enc`. Оба профиля запрашивают ноль B-кадров и ключевой кадр каждые 20 кадров. Для установщика предстоит оценить аппаратный fallback и условия распространения x264 и других кодеков. [Документация DXGI-источника GStreamer](https://gstreamer.freedesktop.org/documentation/d3d11/d3d11screencapturesrc.html), [Media Foundation encoder](https://gstreamer.freedesktop.org/documentation/mediafoundation/mfh264enc.html), [x264enc](https://gstreamer.freedesktop.org/documentation/x264/index.html).

Публикация идёт через `whipclientsink` в MediaMTX v1.21.3. Медиасервер пишет fMP4 и предоставляет встроенную WebRTC-страницу и HTTP API воспроизведения. Для лаборатории выделены один путь и разные случайные пароли для публикации и чтения. По умолчанию все слушатели привязаны к `127.0.0.1`. Для LAN профиль требует TLS и конкретный IPv4. Лабораторный секрет издателя передаётся в аргументе дочернего процесса GStreamer на время прогона, поэтому его следует использовать только для этого стенда. В MVP требуются отдельная идентичность агента, краткоживущие права и передача секрета внутри медиамодуля. [Публикация через GStreamer](https://mediamtx.org/docs/publish/gstreamer), [воспроизведение MediaMTX](https://mediamtx.org/docs/features/playback), [авторизация MediaMTX](https://mediamtx.org/docs/features/authentication).

Отдельный процесс `Ekravio.Capture` проверяет WTS и рабочий стол Windows перед запуском GStreamer и продолжает опрос с интервалом 200 мс. Если сеанс перестал быть активным локальным сеансом или рабочий стол недоступен, процесс завершает GStreamer. Следующий запуск оператор подтверждает вручную. Дочерние процессы наследуют Windows Job Object с `KILL_ON_JOB_CLOSE`. [Активный консольный сеанс Windows](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-wtsgetactiveconsolesessionid), [OpenInputDesktop](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-openinputdesktop), [Windows Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects).

Текущий запуск MediaMTX — нативный процесс в тестовом каталоге. Интеграция Windows Service и `systemd`, расширенный контроль доступа, разрывы, переподключение и квота остаются следующими задачами. Перед выбором серверного runtime проверяем доступность пакетов и запуск на Windows 10 Home. Microsoft перечисляет поддерживаемые выпуски Windows 10 отдельно от других версий Windows. [Матрица .NET от Microsoft](https://learn.microsoft.com/en-us/dotnet/core/install/windows).

## Ввод

Лабораторная проба на .NET 11 опрашивает `GetLastInputInfo` в текущем пользовательском сеансе и запрашивает тип подключения через WTS. .NET 11 выбран по доступному SDK в среде разработки. Вывод — время наблюдения, состояние, качество, наличие нового ввода и тип сеанса. Отсчёт простоя использует монотонные тики. При новой базовой точке, разрыве опроса, скачке часов или подозрительной метке Windows качество помечается как `unavailable`. Причина недоступности рабочего стола без события WTS остаётся `unknown`. [GetLastInputInfo](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getlastinputinfo), [WTSQuerySessionInformationW](https://learn.microsoft.com/en-us/windows/win32/api/wtsapi32/nf-wtsapi32-wtsquerysessioninformationw).

Для каждого удалённого сценария нужно подтвердить покрытие тестом. Если опрос пропускает штатный удалённый ввод, отдельно исследуем дополнительный сигнал с агрегацией внутри сеанса. Объединение нескольких сеансов, доставка и дедупликация агрегатов относятся к MVP.
